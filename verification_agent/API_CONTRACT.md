# Verification Agent (Person 4) API Contract

This document outlines the API contract for the Multimodal Fusion + Verification Agent. It expects a single merged POST request containing the payloads from the Contract, Evidence, and Forensics agents.

## Endpoint

**`POST /verify`**

## 1. Request Schema

The endpoint accepts a JSON object with three root keys: `contract`, `evidence`, and `forensics`. To support anomaly detection for missing data, **all fields inside the sub-payloads are optional**. However, this is the expected shape:

```json
{
  "contract": {
    "milestone": "string (name of the milestone)",
    "quantity": "float (quantity of work done)",
    "unit": "string (unit of measurement)",
    "deadline": "string (ISO 8601 datetime)",
    "specification": "string",
    "source_reference": "string (ID or URL to contract)"
  },
  "evidence": {
    "claim_record": "object (raw claim data)",
    "gps": "string ('latitude, longitude')",
    "timestamp": "string (ISO 8601 datetime)",
    "coordinates_in_boundary": "boolean",
    "cv_relevance_score": "float (0.0 to 1.0)",
    "detected_stage": "string"
  },
  "forensics": {
    "is_duplicate": "boolean",
    "similarity_score": "float (0.0 to 1.0)",
    "manipulation_flag": "boolean",
    "ai_generated_flag": "boolean",
    "metadata_consistency_flag": "boolean",
    "forensics_confidence_score": "float (0.0 to 1.0)"
  }
}
```

## 2. Response Schema

The endpoint returns a structured Verification Output detailing the risk level, explanations, and any contributing anomalies.

```json
{
  "verification_status": "string (VERIFIED | PARTIALLY_VERIFIED | DISPUTED | INSUFFICIENT_EVIDENCE)",
  "evidence_confidence": "float (0.0 to 1.0)",
  "explanation": [
    "string (traceable explanation referencing specific fields)"
  ],
  "risk_level": "string (LOW | MEDIUM | HIGH | CRITICAL)",
  "inspection_priority_rank": "integer (1 to 100, where 1 is highest priority)",
  "contributing_factors": [
    {
      "reason": "string (description of the anomaly)",
      "triggered_fields": [
        "string (e.g. 'evidence.gps')"
      ]
    }
  ]
}
```

## 3. Example Responses

### A. Clean Case (Verified)
If the upstream agents send data that aligns perfectly with the contract, no anomalies are flagged.

```json
{
  "verification_status": "VERIFIED",
  "evidence_confidence": 1.0,
  "explanation": [
    "Based on `contract.source_reference`, the claimed progress matches the required milestones.",
    "All `evidence` fields align perfectly with contract requirements, and no anomalies were flagged by forensics.",
    "Note: This explanation was generated by the reasoning engine using the fused case data."
  ],
  "risk_level": "LOW",
  "inspection_priority_rank": 100,
  "contributing_factors": []
}
```

### B. Flagged / High-Risk Case (Disputed)
If there are missing fields, metadata inconsistencies, or forensics manipulation flags, the output exposes the specific triggered fields and ranks the priority highly.

```json
{
  "verification_status": "DISPUTED",
  "evidence_confidence": 0.4,
  "explanation": [
    "Multiple discrepancies found between `contract` requirements and `evidence` data.",
    "For example, `forensics` scores indicated potential issues with the submission integrity.",
    "Note: This explanation was generated by the reasoning engine using the fused case data.",
    "Evidence flagged as duplicate (Similarity: 0.99).",
    "GPS coordinates are outside the approved project boundary.",
    "Forensics flagged possible image manipulation."
  ],
  "risk_level": "CRITICAL",
  "inspection_priority_rank": 1,
  "contributing_factors": [
    {
      "reason": "Evidence flagged as duplicate (Similarity: 0.99).",
      "triggered_fields": [
        "forensics.is_duplicate",
        "forensics.similarity_score"
      ]
    },
    {
      "reason": "GPS coordinates are outside the approved project boundary.",
      "triggered_fields": [
        "evidence.coordinates_in_boundary",
        "evidence.gps"
      ]
    },
    {
      "reason": "Forensics flagged possible image manipulation.",
      "triggered_fields": [
        "forensics.manipulation_flag"
      ]
    }
  ]
}
```
